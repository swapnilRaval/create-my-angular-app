## Environment configuration

Files:

- `src/environments/environment.ts` — production defaults
- `src/environments/environment.development.ts` — local development

Values such as `apiUrl` and `appName` are compiled into the browser bundle. **Do not put secrets in these files.** Anyone can read them.

Development defaults:

- `apiUrl`: `http://localhost:5000/api`
- `allowDevLogin`: `true` (disabled in production)

Dev login creates an in-memory admin user so you can explore the shell without a backend. It is not authentication.

## Architecture

| Layer | Responsibility | May import |
| --- | --- | --- |
| `core/` | Singleton services, guards, interceptors, API client | Angular, environments |
| `shared/` | Domain-agnostic UI, pipes, directives, validators | `core` models only when needed |
| `layout/` | Shell chrome: header, sidebar, breadcrumbs, footer | `core`, `shared` |
| `features/` | Pages, feature services, feature routes | `core`, `shared`, `layout` |

Rules that prevent circular dependencies:

- `core` never imports `features`, `layout`, or `shared` UI.
- `shared` never imports `features` or `layout`.
- `layout` never imports `features`.
- Features import other features only when the dependency is intentional (Profile uses `UserService` for avatar upload).

Copy the Users feature when you add Products, Orders, or Leads:

1. Add `features/<name>/` with `pages/`, `services/`, `models/`, and a resolver if needed.
2. Add `routes/<name>.routes.ts`.
3. Lazy-load it from `app.routes.ts`.
4. Add a sidebar item in `core/config/menu.config.ts`.

## Routing

Public: `/`  
Auth (guest): `/login`, `/register`, `/forgot-password`, `/reset-password`  
App shell (auth): `/dashboard`, `/profile`, `/settings`, `/users`, `/users/new`, `/users/:id`, `/users/:id/edit`  
Admin (auth + role): `/admin`, `/admin/users`, `/admin/roles`, `/admin/settings`  
Wildcard: `**` → 404

The root component only renders `<router-outlet />`. Authenticated pages render inside `ShellComponent`, which has a nested outlet.

Route titles come from the `title` field. Breadcrumbs come from `data.breadcrumb`. `withComponentInputBinding()` maps resolver data such as `user` onto page inputs.

`returnUrl` is accepted only when it is a same-origin relative path. Open redirects are rejected.

## Guards

- `authGuard` — signed-in users
- `guestGuard` — login/register
- `roleGuard` — `data.requiredRole`
- `permissionGuard` — `data.requiredPermission`
- `unsavedChangesGuard` — dirty forms (`CanLeave`)

These are not security. The API must enforce authorization.

## Authentication

Preferred model: httpOnly cookie/session + `withCredentials`. Tokens are not stored in `localStorage`.

`AuthStore` holds the current user as signals. `AuthService` talks to `/auth/login`, `/auth/register`, `/auth/logout`, `/auth/me`, `/auth/forgot-password`, and `/auth/reset-password`.

## HTTP and API

`ApiClientService` prefixes `environment.apiUrl`, unwraps `{ data }`, and supports query params. Feature services stay in the feature (`UserService`).

Interceptors:

- auth — always send credentials
- loading — global bar, skip with `SKIP_LOADING`
- error — snackbar + 401 redirect, skip with `SKIP_GLOBAL_ERROR`

## Users CRUD

- `POST /users`
- `PUT /users/:id`

## Troubleshooting

- **API calls fail in development** — start your backend on `http://localhost:5000` or change `environment.development.ts`.
- **CORS / cookies** — the API must allow credentials and a matching origin.
- **Guards bounce you to login** — either enable dev login or implement `/auth/me`.
- **Node engine error** — use Node 22.22.3 or newer.
- **`ng test` missing providers** — add them in `src/test-providers.ts`.
